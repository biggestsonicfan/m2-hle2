# The PS3-style menus (`src/ui/ps3ui*.h`)

The libretro core and the web build present Sonic the Fighters the way its PS3 release
(NPUB30927, 2012) does: the title, the main menu, Arcade / Offline Versus with the PS3's rule
settings, the pause menu, Help & Options, and the online lobby (Player Match, the room list, the
VS lobby, the ROOM MATCH list, the result). This directory holds the tools that build and grade
them.

**No Sega asset is in the repo.** The PS3 release draws its menus with the Project DIVA engine:
AET layouts (After Effects layers with keyframes) placing sprites from texture atlases, text
drawn by the program into empty "placeholder" layers, and two bitmap fonts. Here:

| PS3 | this repo |
|---|---|
| AET layouts (`auth2d/n_cmn.farc`) | `src/ui/ps3ui_layout.h`: the layers' timing, keyframes, blend modes and which sprite each shows -- numbers, generated by `gen_layout.py` |
| sprites (`sprite/n_cmn.farc`, DDS atlases) | `src/ui/ps3ui_sprites.h`: every sprite painted by code from a model (borders, landmark colours, fitted falloff curves), graded against the original by `grade.py` |
| fonts (`fontmap.farc`, `n_fnt`) | the nearest OFL fonts (`bake_fonts.py`: Anybody, M PLUS 1p, M PLUS 1 Code; licences in `licenses/`), placed with the PS3's per-character ink metrics so strings sit where the PS3 puts them |
| the program (menu tasks, `Text_Printf`) | `ps3ui_screens.h`, `ps3ui_app.h` (online), `ps3ui_shell.h` (offline): the screens, rebuilt from the PS3 EBOOT in Ghidra |

## The pieces

- `ps3ui.h` -- the compositor: a canvas addressed in 1080p layout units (the PS3 authors at
  1920x1080 and shows 1280x720), straight-alpha sprites sampled bilinearly, the two blend
  modes the menus use (normal, additive), text through stb_truetype, and an AET player.
  A canvas either rasterises on the CPU (the tests) or records a **draw list** of textured
  quads (`cv->dl`) for the GPU.
- `ps3ui_gpu.h` -- draws a draw list with sokol_gl: each sprite becomes a texture once, glyphs
  go into one atlas. **Frontends use this path only**: the CPU path is 24 ms a frame at 720p.
- `ps3ui_app.h` -- the online lobby (the PS3's TaskSession) over `net/netplay.h`.
- `ps3ui_shell.h` -- the offline shell around the board, for the Console version.
- `ps3ui_screens.h` -- shared screens and helpers (the VS lobby, the hint bar, text styles).

## Tools

| tool | what it does |
|---|---|
| `extract/extract.py <rom.psarc> <work>` | decodes your own copy of the PS3 data into `<work>` (outside the repo): AET JSON, sprite PNGs, font metrics, strings. `aetrender.py` composites a layout from the real sprites, `measure.py` profiles a sprite's pixels |
| `gen_layout.py <work>/aet/n_cmn.json <work>/sprites/sprites.json <work>/sprites/fontmap.json` | regenerates `src/ui/ps3ui_layout.h`. The compositions it keeps are listed in `WANT` at the top |
| `bake_fonts.py --anybody ... --mplus ... --mcode ...` | regenerates `src/ui/ps3ui_fonts.h` from the OFL fonts (google/fonts) |
| `ps3ui_render` (`tests/ps3ui_render.c`, built beside the tests) | renders on the CPU, no GPU: `sprites <dir>` every painted sprite; `vs <png> [w h frame]` the VS lobby as in the reference capture; `app <dir>` every online screen off a made-up netplay status; `shell <dir>` every offline screen |
| `grade.py sprites --ours <dir> --ref <work>/sprites/n_cmn/spr` | each painted sprite against the PS3's, mean / p99 / max premultiplied error, worst first |
| `grade.py screen --ours <png> --ref <capture> --out <dir>` | a rendered screen against a capture of the real one (an RPCS3 window capture: the placement is searched, since a window capture is rarely a clean scale), with a side-by-side and a diff map |

Where things stood when this was written: the VS lobby against an RPCS3 capture, mean error
4.0/255 over the frame; the painted sprites, mean 3.3 over 80, the frame pieces under 1. The
biggest remaining differences are letterforms (the fonts are not Sega's).

## Facts that took finding

- **Every scene is 1920x1080 at 60 fps.** Keyframes are Hermite in frame units; a layer's
  keys are in its parent composition's time; a child composition runs at
  `(t - start) * time_scale + offset`; layer 0 is on top.
- **Windows run on markers**, not on a fixed table: `sta_s..sta_e` open, `neu_s..neu_e` idle
  (looped), `end_s..end_e` close, on the layer that places the window in its scene
  (`connect_win` idles 10..189, most 10..69). A window must be ticked by the task, not by the
  draw: a frontend that skips drawing would otherwise leave windows stuck opening.
- **One-shot effects hold on the last frame of their placing layer** (`eff_ready` ends at 60;
  its children run to 70).
- **Text is the program's**, at placeholder layers (`head_tit_ct`, `p_tag_1p_lt`, ...; `_lt`
  top-left, `_rb` bottom-right, `_ct` top-centre, `_c` centre). A placeholder's box is its
  own w x h, so a `_rb` placeholder's corner is `m(w, h)`, not `m(0, 0)`.
- **The button glyphs** are font characters: U+E000..E003 in the strings are drawn as the PS
  faces (circle, cross, triangle, square) on a Western console, where cross confirms. Here
  they travel as `\x01`..`\x04`.
- **The PS3's Yes/No dialog starts on No, and circle does nothing**: to answer no you move to
  No and press cross. Every shell menu clamps its cursor; the room list wraps.
- **The countdown in the VS lobby is 30 s** (5 s in a room of three or more), and at zero
  the PS3 readies the player.
- **Signal bars**: < 80 ms full, < 142, < 204, else none; unknown is the crossed-out icon;
  your own row has none.
