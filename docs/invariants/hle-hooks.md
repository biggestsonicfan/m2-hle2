# HLE Hooks (game-specific addresses, board-level patterns)

Part of m2-hle2's load-bearing invariants, indexed in [CLAUDE.md](../../CLAUDE.md): facts reverse-engineered or debugged into the emulator, in no datasheet. Do not re-derive them.

These addresses are STF-specific. The **patterns** repeat across the catalogue — every Model 2 game ships some form of COP self-test and frame-loop entry; the addresses change per ROMset.

- **`CoProcessorErr` at `0x74E4` (STF)** must be bypassed. Return via `locals.rip` (saved return address from the call frame), NOT normal IP advance. Without this, STF hangs at the Sega logo. Every Model 2 game will have an equivalent — find by symptom (hang on boot, COP self-test loop).
  - *In this project* the COP answers the self-test itself, so no profile carries a bypass at `0x74E4`. What STF hooks instead is the failure hang, `co_processor_error_hang` at `0x77F8` (`sfight_hook_cop_err_hang`; FV has no hook there yet, `fvipers.h`): it halts the CPU and logs g4's error code so the UI stays live. The `locals.rip` return is `hle_ret` (`hle_hooks.h`), which hooks that skip a whole function (`check_timer_4`) still use.
- **No hook waits for a vblank or a timer: the board raises them on the i960's own cycle clock, and the game's handlers end its wait loops** (Pinboard #253, `irq_timer.h`). The vblank comes every 434,600 cycles (the board's 57.52 Hz at 25 MHz, `IRQT_FRAME_CYCLES`; 416,667 until #1075) and a slice runs exactly to it; the timers always count cycles (`--live-timers` is accepted and does nothing). STF's `interrupt_wait` 0x1768, `interrupt_wait_b` 0x11580, `_idle` 0x11610, `check_timer_4` 0x4A55C and `check_timer_4_spin` 0x4A58C are gone, and FV's 0x2238, 0x1184C/0x118DC and 0x4A88C with them: the Timer handler sets the flag at `0x50008C` itself, and VsyncScr (STF 0xC40, FV 0x13A0) runs as the vblank interrupt. Do not bring a wait hook back. It ran VsyncScr with `hle_call` at the game's convenience, ended the slice wherever the game's frame happened to end, and needed `EMU_FRAME_STEPS_MAX` to keep the sound board running through a load.
  - **The game's frame still ends at `variable_diff_calc`** (STF ~`0x11A04`, FV 0x11C80): the frame-pace hook marks the display-list capture there (`dl_game_frame_edge`) and makes the match_replay jump (`hle_game_frame_edge`), because MAME's `match-replay.lua` and every capture sample there. Made at the vblank, which falls mid-frame, the jump moved the replay fight off MAME at +127; at the hook it holds to +321, as before.
  - `EMU_STEPS_PER_SLICE` (500,000) is now only a cap: a slice cannot run more instructions than a vblank's 434,600 cycles. A lower `--steps-per-slice` ends slices short of the vblank and the board runs the same: `det_digest --steps-per-slice 150000` differs only in frame 1's RAM, where the warning skip, written once a slice, lands.
  - *Bugs this took with it:* `_idle`'s static survived a board reset, and FV's `read_sw` hook zeroed the last pad (0x500700) before every read, so every held button looked newly pressed.
- **Never hook `clip_point_check_yoko` / `clip_point_check`** (STF `0x28188` / `0x28250`, FV `0x236BC` / `0x23784`). They return nothing in `g0`. Each runs a point list through op `0x29` and writes one outcode byte per point to `0x50E000` (`0x90` behind the lens, `0x81`/`0x82` off the left/right edge). `area_clip` then draws a ground chunk only when the AND of its four corners' outcodes is zero, and finally draws the chunk the camera stands over.
  - *Symptom that surfaced this in STF:* stage ground chunks popped in and out as the fighters moved. The hooks skipped the write, and `0x50E000` is scratch that `rob_spd_control` fills with fighter X/Y/Z floats, so the cull was ANDing position bytes. Measured by `tools/grade-cull.mjs`: 0 of 299 frames right and 998 chunk toggles with the hooks, against 17 for the ROM's rule; exact in 599 of 599 without them.

- **STF's texture loader runs in C, one row at a time, and the board cannot tell** (`profiles/m2_texload.h`, Pinboard #178, #228). Hooks on the first instruction of each row's body (`unpack_lod_data` 0x4B9B4, `send_beta_data` 0x4BD30, `send_lod_data` 0x4BF64, `send_lod_data_q_sub_norm` / `_anim` 0x4C1F8 / 0x4C334) port that row instruction for instruction: every register and temporary, the condition code, every store in order from its own address, and the instruction count and cycles from the ROM's words. The run loop charges them as the i960's (`g_hle_room` / `g_hle_extra`, `hle_hooks.h`). The i960 runs everything else: the preamble, `check_timer_4_result`, the yield between rows and the resume. A row is left to the i960 when it would not end before the slice does, when the live timers would come due inside it or an interrupt is pending, when a watchpoint is armed, or when the code's FNV is not the known one.
  - **Do not go back to hooking the routines whole** (#151's first version). Texture RAM came out the same, but a page went in one call where the ROM yields on a timer-4 budget. The game's `rand` (0x66B0) mixes in the timers, so `random` (0x500098) moved from frame 556 of attract on, and with it the CPU fighter's choices. That needed a `NETPLAY_PROTO_REV` bump; the row hooks do not.
  - `det_digest --cpu` (texram, registers, cycles) against `--texload-i960` is byte-identical frame for frame over select, the VS screen and a fight, with the timers frozen and live alike (and again since they are always live, #253), on x86 and on the ARC-S's A55. 89-98% of a load frame's i960 instructions run as C rows, at ~1.4 ns each on x86 against ~6 interpreted, and ~8 ns on the A55; the ARC-S's VS-screen load frames went from 34-45 ms to 20-23 ms.

- **`--gems-i960` / `--gems-cop` run Sega's own C from Sonic Gems Collection in place of STF's trapped i960 functions and the COP firmware** (`core/gems.h`, Pinboard #454). The Gems port (GameCube) traps ~45 heavy i960 functions into native C and has one C function per COP command. The converted C is decompiled Sega code and **is not in this tree and must not be added to it**: it is the owner's own repository [gems-c](https://github.com/biggestsonicfan/gems-c), the submodule `vendor/gems-c` (Pinboard #532), which carries the raw decompiles (gems-decomp) as its own submodule `decomp/`: init it with `git submodule update --init --recursive vendor/gems-c`. Its `gems_all.h` is generated and not tracked: CMake runs its `gen_all.py` at configure, which reads `decomp/SHARC/INDEX.md`, so building with it needs Python 3. CMake's `M2HLE_GEMS_DIR` (a directory holding `gems_impl.h`) defaults to it when it is checked out; the CI fetches only the submodules it builds, so the canary has none, and a build without it gets options that log that they do nothing. After changing the C, commit and push it in gems-c first (and lizard it, gems-c's README), then commit the new submodule pointer here. `--gems-verify` runs each trap both ways (C on a copy of the board, then the i960 to where the C resumed) and logs what differs; the board carries on from the i960's run. `M2HLE_GEMS_VERIFY_ALL=1` checks every call instead of one in 32 after the first 256.
  - **A profile hook inside a trapped function is run by the C, or the trap stays with the i960** (`gems_inner`, `gems_trap_left_to_i960`; Pinboard #509). The Console profile's head tilt (`0x30608`) is inside `get_frame_dat` (`0x304C8`): the C's fade-out loop loads r10-r12 as the ROM's loop holds them and calls the hook, and `--gems-verify --profile sfight_console` holds every call exact. A Gems folder whose C does not name the hook (`GEMS_INNER_SITES`) leaves that function to the i960 on that profile, as before. A new hook inside any of the 47 trapped functions needs the same, or a row in that table.
- **`--ages-i960` / `--ages-verify` run Sega's own C from Sega Ages 2500 Vol. 19 and Vol. 16 (PS2) in place of Fighting Vipers' and Virtua Fighter 2's patched i960 functions** (`core/ages.h`, Pinboard #996, #1043). The PS2 writes an extension opcode over 46 functions of the unmodified `fvipers` (Revision D) program; its ABI is Gems' (called with 1, pops the frame, returns 0), so `ages.h` runs on gems.h's runtime, `gems_run` and verifier (`gems_verify_in`, tagged `ages-verify:`). The C is the owner's [ages-c](https://github.com/biggestsonicfan/ages-c), not in this tree: the submodule `vendor/ages-c` (Pinboard #1043), which carries ages-decomp as its own submodule `decomp/` (`git submodule update --init --recursive vendor/ages-c`). CMake's `M2HLE_AGES_DIR` defaults to it when it is checked out, as `M2HLE_GEMS_DIR` does to gems-c; the CI fetches neither, and the same rules hold: lizard and push the C in ages-c first, then commit the new submodule pointer here. It and `--gems-*` share the one extra-hook slot (`g_hle_extra_*`): `ages_apply` runs after `gems_apply` and takes it only on a set `ages_impl.h` serves (`ages_sets[]`: `fvipers`, `vf2`; not the clones). A netplay session turns it off. FV: 38 of the 46 roots are hooked, all exact under `--ages-verify` (ages-c's README lists the 8 that are not). VF2: all 11 patched functions with a site are hooked (set_obj at its 140 `call 0x7c60` sites); attract runs 7 of them exact under `--ages-verify`, happa_disp (stage 5) and recog_sample (player input) were exact on scripted games, and set_obj_common / set_obj_same never ran (ages-c's README, "Virtua Fighter 2"). VF2 is Model 2A, so its C drives the TGP over the bus (`ages_st32`/`ages_ld32` at g11 + g12), never `ages_cop_*`, and the verifier's snapshot holds and compares `g_tgp`. VF2's PS2 C returns its skip in i960 words (resume = site + R*4); in gems' convention that is R*8.
  - **The verifier's float-close never covers a denormal** (`gems_float_close`): a small integer in a word (a face number, a flag) reads as a denormal float, and within 1e-6 of any other such word. A wrong face slot passed as float-close until this (#996).
  - Neither option is the board: a trapped function is charged as one instruction (the timers, and so `rand`, see less time), and Gems' COP is Sega's C, which gems-c builds with the board's float rounding (no FMA) but which is still not the SHARC firmware. A netplay session turns both off (`g_hle_extra_session_off`). Our own `set_obj` hook (COP 0x78) stays; Gems' version is kept beside it for reference.
  - *What the comparison found in our board:* `Fn_area_coli`'s NaN compares and the i960's unordered `cmpr` (above). Gems' C handles a NaN as the hardware does, so a difference against it is worth checking against MAME before blaming the C.
- **SKY EYE mode moves the camera by writing STF's camera record at `loc_1F3A0` in `camera_control`, not with the debug menu's `debug_flag` bit 5** (`core/sky_eye.h`, Pinboard #265). Bit 5 is what the menu's SKY EYE page sets to stop `camera_work`, but `control_init`, `collision`, `enemy_control`, `object_init`, `adv_movie_cont` (attract goes blank) and a dozen more skip their work on it too. `loc_1F3A0` is where the `camera_work` path and the bit-5 path meet, before `area_check` and the view read `fa_camera` +0x18..+0x28. A stage asked for has arrived only when the loaded record's texture words (`0x504800`+0x0C) match the ROM record's (`0x8F3D0` + n·256 + 0x0C); holding `stage_num` alone is not arriving.

- **`_idle`'s wait for the vblank is skipped on the cycle clock, in whole iterations, and the board cannot tell** (`profiles/m2_spin.h`, hook at `0x11610`, Pinboard #294). Since PR #163 the loop (`ldob 0x500000, r3` + `cmpibe r3, g0`) ran interpreted until the interrupt: two thirds of STF's i960 instructions. The hook decodes the loop from memory, and runs as many iterations as end before the timers' horizon (`g_irqt.horizon`), charging their instructions and cycles as the i960's; the i960 runs the one the horizon falls in. It declines with an interrupt pending, a watchpoint armed or under two instructions of room. `det_digest --cpu` against `--spin-i960` is identical over 4000 frames of attract and a 9000-frame scripted game; on the ARC-S the i960 thread fell 36-51% and the process 10-13%.
  - **Homebrew gets the same skip for its own waits** (`m2_spin_find`, Pinboard #481): `sfight_homebrew` scans the program at install for an absolute load followed by a compare-and-branch back to it, and hooks each loop found (`g_hle_spin_sites`). A single-stepping caller (`i960_step_hot`, `det_digest --trace`) passes a room of 1, so the skip never runs there; a PC histogram from a trace shows the waits the real run skips.

- **Every profile says what it does with the region** (Pinboard #942): `game_quirks_t.region` (`game_region_use_t`). `REGION_HOOKED` names two hooks in the profile's table, at two addresses: `factory_default` (`g_region` in the country's factory default) and `over_saved` (after the game accepts a saved block: `g_region` over the working copy's country, at `country()`, when `g_region_over_saved` is up). A factory-default hook alone is not enough: a kept backup RAM / EEPROM would then ignore `?lang=` (#948). `tests/region_test.c` runs every `over_saved` hook on a bare bus (the saved country stays with the flag down, becomes `g_region` with it up). Otherwise the kind says why there is none (`REGION_PROGRAM_ROM`, `REGION_HOMEBREW`, with `why`); every one of those kinds is taken only by the profiles the test lists, each as its listed kind (`vonj` and `airwlkrs` program ROM, `m2snake`/`sfight_homebrew` homebrew), so a new game skips the hooks only by editing the test. The web page's language picks the region (`m2hle-game.js` → `--region=`): English USA, Japanese (`?lang=ja`, or `jp`) Japan, any other Export, over saved backup RAM too. **Sega Rally**: its settings block (`0x202010`, CRC16 + length 0x24 + GAME ASSIGNMENTS; COUNTRY `0x202019`) lives in the 315-5649's serial EEPROM (93C46 on `0x1C00000`), not in backup SRAM. `country_default` at `0x5A19A4` (RAM; the factory defaults at `0x5A1978` store COUNTRY = 0, the next instruction is where the hook writes `g_region`); `settings_checked` at `0x5A1CD0`, where the boot goes on after `0x5A1C80` has read the block and checked its CRC (the defaults run first when it fails), writes `g_region` over a saved COUNTRY when `g_region_over_saved` is set. The board has no EEPROM yet (DO reads 1), so every boot fails the CRC and takes the defaults today. Native `--region-over-saved` sets the flag as the web's `--region=` does. Japan (0) is the ROM's default and MAME's: the graders' `--region japan` leaves the board as it was; USA, now the default, is proto rev 21. **Virtual-On** (`vonj`): no country setting, the program ROM is Japan's (MAME's `von`/`vonu` are other program ROMs). **Air Walkers** (`airwlkrs`, Pinboard #1073): no country setting either; the only dump is Data East's AOU show build ("Ver 0.99.99a JAPAN 97-01-23 AOU SHOW version" at program `0xC6A50`), whose warning names only Japan, and COIN / GAME OPTIONS have no country, so `?lang=` changes nothing on the board. **Fighting Vipers** (Pinboard #1025): COUNTRY is byte `0x3350` of the settings block (backup `0x1D03340`, 29 bytes summed against `0x1D03302`; version 18 at `0x1D03306`); the boot copies backup `0x1D00000` to work RAM `0x599000` (`0x44E4`), so the game reads `0x59C350`. `country_default` at `0x5E4D4`, after the factory settings (`0x5E358`) store 0 to both copies (`0x5E4C4`, `0x5E4CC`); `settings_loaded` at `0x46F4`, where the boot goes on (only from `b` at `0x4518`) once the copy is made, whichever path checked it. The test menu wraps COUNTRY 0..2 (Japan, USA, Export), the screens: Japan's warning, USA's FBI "Winners don't use drugs", Export straight to the SEGA logo. Before #1025 FV always booted Japan; proto rev 28. **Virtua Fighter 2** (Pinboard #1055): the same block as FV (COUNTRY `0x3350`, base pointer `0x50016C`, backup copied to `0x599000`). 2.1: `country_default` at `0x6029C`, after the factory defaults (`0x6010C`) store 0 to both copies; `settings_loaded` at `0x6E1A4`, just after the boot points `0x50016C` at `0x599000` (`0x6E19C`, both paths). The clones are other builds of the same code: vf2b `0x5E020`/`0x6BEEC`, vf2a `0x5C280`/`0x6A12C`, vf2o `0x5C240`/`0x6A0EC` (found by their bytes). Japan shows the "only in Japan" screen (`0xA804`). `--region japan` is det_digest-identical to the build before the hooks; no proto bump (VF2 was new in the same PR stack).

- **STF has two profiles on one ROM set, and the CONSOLE one is the default** (`sfight_console`, `profiles/sfight_console.h`; the arcade game is `sfight`). It adds the Honey / hidden-character traps Sega's console emulator DLL installs (its table at DLL RVA `0x1E8870`, named in YAMP's `StfHooks.inc`), ported handler by handler from Ghidra. One of them, `get_frame_dat+0x140`, zeroes the head-tilt term of the motion blend for EVERY fighter, so the console profile does not play attract's replay fight the way MAME does. Anything held against MAME or the explorer must run `--profile sfight`: `tools/lib/m2hle.mjs` passes it by default, and a new launcher has to as well.
  - **Both STF profiles power up as USA** (`g_region`, `--region japan|usa|export`): the hook at `0x62688` (`init_game_assignments`, the `stob` of `country_val`'s factory default) loads it on every boot whose backup RAM is blank (see "Backup RAM" below). A player's saved backup RAM keeps its own region, so there `--region` (and the free-play and DAMAGE defaults below) apply only after the test menu's INITIALIZE, but on the web: its `--region=` sets `g_region_over_saved`, and `settings_loaded` (`0x6974`, where main's call to the backup-RAM-to-RAM copy at `0x3634` returns) puts the region in the working block's country (`+0x12`) over the saved one. The saved block itself is left alone. MAME's sfight boots as Japan, so anything held against MAME must also pass `--region japan` — `tools/lib/m2hle.mjs` does by default. USA skips the Japan-only warning, adds the FBI picture to attract and uses the US names.
  - The console build's ROM images (YAMP's loose `rom/stf_rom/*.bin`) are byte-identical to the arcade set's code, data, EPROM and polygon ROMs; only the texture ROM's layout differs. Every console difference is in the DLL's traps, none in data. Honey's VS portrait (sprite `0x96`) is her silhouette over a "???" plate, and that is correct, not a missing asset.
  - **The Console profile boots on FREE PLAY**: `sfc_hook_free_play` at `0x62754` (`sram_clear_for_coin_assign`) stores 26 in CREDITS_REQUIRED (`0x1D03324` and its RAM copy `0x59C324`), where the factory default is 0. The ROM itself tests for 26 (`26:FREE PLAY`). The Arcade profile still boots on coins. Coins do nothing on free play, which is harmless for a script that inserts them anyway.
  - **DAMAGE** (`g_damage_real`, `--damage real|normal`) is the GAME ASSIGNMENTS flag byte's bit 7 (`0x59C353`), put in by `damage_default` at `0x62674` in `init_game_assignments`, like the region. The ROM's labels run the other way from what you might guess: the test menu's `DAMAGE_TYPE` is {NORMAL, REAL} by the bit, and `ketchup` (`0x19740`, called by `damage_calculation`; `ACT_RC_DOWN_ATTACK` too) scales a hit by the energy gap only when the bit is CLEAR. So **NORMAL (0, the factory default) is the catch-up damage and REAL turns it off.** Only a room on our server sets it (the owner's `damage_real` in the room state, NORMAL unless the host picks REAL, as the console plays); everything else boots NORMAL too, so the graders are untouched.
  - **CPU difficulty** (`g_enemy_rank`, `--enemy-rank`, the desktop's Profile menu, the PS3 menus' Difficulty) swaps only the AI table: `sub_3B22C` loads `match_enemy_rank_data[rank & 3]` at `0x3B274`, and the hook there (`SFIGHT_BASE_HOOKS`, both profiles) hands it Easy..Hardest or one of the two tables the ROM carries and never points at, `0x93428` and `0x93728` (Extra 1 / 2; each 0x300 bytes, 32 a stage). **Never store 4 or 5 in the cabinet's ENEMY RANK byte** (`0x59C342`): `var_diff` at `0x11AC8` indexes `byte_11BD4[rank*8 + n]` unmasked, and past row 3 that is float data. The PS3 menus' Extra choices keep the cabinet on Hard. A netplay session plays the cabinet's table (`g_hle_netplay_board`).
  - **VS mode** (`g_vs_mode`, `--vs-mode`, off by default) is the DLL's trap at `0xE584` (`next_round+0x1A4`), in `SFIGHT_BASE_HOOKS` for both profiles. A decided versus match jumps to `0xF524`, the ROM's own "both continue" path, so both players go back to character select. Off, the winner stays on against the CPU and the loser is out. The DLL's VS stage pick (`0xAF84`) draws from host RNG and is not ported, and neither is its `vs_match_count = 3`.
  - **The House of the Dead keeps COUNTRY in its 93C46 EEPROM** (Pinboard #1040, proto rev 30), not backup RAM: 0x1DF90 reads the EEPROM to 0x51F090 at boot ("S32A", version 0x6655, a sum at 0x51F098 over 38 bytes from 0x51F09A, a mirror at 0x51F0C0); COUNTRY is 0x51F0A9, 0 Japan / 1 USA / 2 Export, which 0x13CD0 copies to the game's 0x51F111. `country_default` at 0x1E0A8 (after 0x1E1D0's factory settings, before 0x1E0C0 sums and writes them) and `settings_loaded` at 0x168C8 (`call 0x13CD0`). The addresses are hotdo's, the container's `hotd.zip`; `hotd_install` leaves both hooks idle, with a warning, on any other program (Rev A's is untested). Japan is the ROM's default and MAME's: Japan boots to the warning screen, USA to the FBI's "Winners don't use drugs", Export straight to attract.
  - **Fighting Vipers has VS mode too** (Pinboard #1031, proto rev 29): `fvipers_hook_vs_rematch` at `0xEAC0` (`vs_game_continue_check_ex+0x18`, `ldob 0x500065`) is the trap Sega's PC emulator for FV sets there (YAMP `docs/fv-hle-hooks.md`, index 36): OR 5 into `0x500248` / `0x50024C` and jump to `0xF7BC`, the ROM's "both continue" path, so `fvipers` is `vs_rematch` and a netplay or GGPO room's versus matches go back to select. The DLL's other host hooks (its rand and VS stage picker on host RNG, the texture-budget wall clock) are what a host emulator needs to stay in sync; this board runs the ROM's own, so none is ported.
- **Virtual-On (`vonj`, `profiles/vonj.h`) has no hooks**: it is the board's defaults with the uploaded-program COP (cop.md), interrupts from the ROM's own table (`irq_vectors`), the frame edge at the vblank and the comm board with nobody on the link (memory-bus.md). Its two levers are IN1 (left) and IN2 (right), active low (MAME `INPUT_PORTS_START(von)`): the left lever is player 1's directions, the right player 2's, each lever's trigger and thumb button B1 / B2; P1 B3 holds both triggers and P1 B4 both dashes. Two actions can share a bit, so `input_action_up` keeps a bit another held action still asks for. The vblank handler (`0x18B0`) copies the inputs at `0x2CB0` into held / pressed / released words at `0x50249C-0x5024A8`; the coin is IN0 bit 0 and START bit 4, and credits live in backup RAM at `0x1D00038`.
