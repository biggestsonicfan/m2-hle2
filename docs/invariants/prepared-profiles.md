# Prepared profiles (`registry.h`, `board/model_table.h`, Pinboard #660)

Part of m2-hle2's load-bearing invariants, indexed in [CLAUDE.md](../../CLAUDE.md): facts reverse-engineered or debugged into the emulator, in no datasheet. Do not re-derive them.

- **A game no board here can run yet is a prepared profile** (`g_prepared_profiles`, `registry.h`; Pinboard #660): a ROM recipe (`core/rom_recipe.h`, MAME's ROM_START lines as data, the shape of noclip's `regions`), the model table noclip reads, no install function, and a `preliminary` sentence saying what the board lacks, which every front end shows instead of "no profile". None is prepared today; making one run means moving it into `g_profiles`, as The House of the Dead (Pinboard #1034: the 2C core and the light guns), Daytona USA (#1035: the Model 1 I/O and sound boards, [model1-boards.md](model1-boards.md)) and Virtua Cop (#1286: the Advanced Model 1 I/O board) were, and `prepared_test` keeps checking a moved profile's noclip reads. The model-table entry layout is the profile's (`game_quirks_t.model_layout`, `board/model_table.h`: 1995's, Virtua Cop's, Daytona's, as noclip's `readModelEntry`); read the table only through `profile_model_table` + `model_entry_read`, never at fixed +0/+4/+8, and turn a mesh pointer into a polygon-ROM offset only with `model_mesh_resolve` (noclip's `meshOffsetOf` plus `decodeModel`'s bound; polygon RAM is refused). A table may run on into a second one: Virtua Cop's models 0x4D2–0x4E2 are read at 0x8693F0 + n × 16, the same n from that table's own base (`model_table_past_from` / `_offset`, noclip's `modelTable.past`); their headers are in texture RAM, which `prepared_test` fills as the game does at game start (0x800 words to 0x4000 from data 0x81D3DE). Whether a model has a texture header stream is `geo3d_model_have_mat` (an address of 0 counts where the layout says `mat_at_zero`: Virtua Cop's). `geo3d_mesh_reads` reports what the decoder reads of a mesh (a polygon-ROM model's, or with `obj_mesh` a polygon-RAM object's), and the header fields it decodes, and `prepared_test` holds both, and the emitted normals and bit 128, to noclip's `decodeModel`. NOCLIP-SYNC.md §6.3 to §6.8 have the parity checks; §6.8 has the ones made against MAME's RAM dumps.
- **A runnable profile's model table is held to the explorer too** (Pinboard #1458): Sega Rally (`srallyc.h`: 1508 entries at data 0x864B40), Dynamite Cop (`dynamcop.h`: 19432 at 0xD40000, one table for its five builds, 50 entries empty) and Air Walkers (`airwlkrs.h`: 2026 at 0x58DD50), all the 1995 layout with the 1995 mesh-pointer arithmetic (subtract 0x02000010, add 0x10), as `prepared_test` holds them to noclip's `decodeModel`. The numbers come from `tools/noclip-reads.mjs`, which prints the `noclip_reads_t` initializer for a set from the pinned submodule; a model table found for another set goes in the same way. Air Walkers' intro city (model 555) is one mesh of 5441 records: the board has no cap on a mesh's length, it walks to the end record, so `GEO3D_IA_MAX_VPS` (8192) must cover the longest mesh of every set with a table here, and the tool's first line names it.
- **A prepared profile can load its set without running it**: a `load_fn` and no `install_fn` (a parent zip too, if it is a clone), and `preliminary` naming what is missing. `dynamcopc` (Dynamite Cop, Model 2C) was one until its MB86235 TGPx4 had a core (Pinboard #1021; cop.md, "Model 2C TGPx4").
- **A recipe can name a BIOS zip** (`rom_recipe_t.bios`, Pinboard #1286), loaded from the folder the game's zip is in (`rom_recipe_sibling`), and its parts are looked up there after the child and parent zips. When a zip has a file with the right name but the wrong CRC, the loader takes the file with the right CRC from the child or parent zip, under whatever name it has (`zip_extract_from_set`): daytonagtx.zip has bank0.bin and bank1.bin the other way round from MAME's list. `rom_recipe_extract` reads one file that isn't in the recipe's regions (GTX's protection banks).
- **The rest of MAME's Model 2 library runs from one header** (`profiles/m2_library.h`, Pinboard #1872; desktop only, `#ifndef M2HLE_WEB`): 21 sets, each a recipe made by `tools/mame_rom_recipe.py` from MAME's `ROM_START`, an install (`m2lib_install`: the board's COP, the 5881 key if MAME has one, the PRCB start), an input map and analog layout from MAME's `INPUT_PORTS`, and `REGION_TODO`. Every board gets MAME's comm board alone on the link (`m2comm_install`, offset 0x1C0): Super GT 24h and Over Rev stop at "CHECKING NETWORK" without one. The container's zips are not always MAME's parent: `dynabb.zip` is `dynabb97` (`m2lib_load` tries the other recipe quietly), `indy500.zip` `indy500to` and `stcc.zip` `stcca` (`rom_recipe_t.older`). Where they stop is where MAME stops: Sega Ski Super G on DRIVE BOARD TROUBLE, Manx TT (DX) on its motion-slider check, and Sega Water Ski's sound program (epr-19967, its first 0x400 bytes repeated) runs off into data in both.
